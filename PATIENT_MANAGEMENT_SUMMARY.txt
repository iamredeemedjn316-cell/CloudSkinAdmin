COMPONENT ARCHITECTURE
================================================================================

STATE MANAGEMENT:
  • showEditModal: Controls edit modal visibility
  • editingPatient: Patient being edited
  • patientList: Master list of all patients
  • showConfirmModal: Controls confirmation modal
  • confirmAction: Tracks action type and patient ID
  • actionMenuOpen: Tracks which menu is open

HANDLER FUNCTIONS:
  • handleEditPatient(patient) - Opens edit modal
  • handleSavePatient(updatedPatient) - Saves changes
  • handleArchivePatient(patientId) - Triggers archive
  • handleDeletePatient(patientId) - Triggers delete
  • handleToggleStatus(patientId) - Triggers status toggle
  • confirmActionHandler() - Executes confirmed action

HOW IT WORKS - WORKFLOWS
================================================================================

EDITING A PATIENT:
  1. User clicks pencil icon (✏️) on patient row
  2. Edit Patient Modal opens
  3. User updates desired fields (name, phone, email, DOB, address)
  4. User clicks "Save Changes"
  5. Modal closes
  6. patientList updates with new values
  7. Table re-renders showing updated information
  8. User sees changes immediately

TOGGLING STATUS:
  1. User clicks three-dot menu (⋮)
  2. Action menu opens
  3. User selects "Toggle Status"
  4. Blue confirmation modal appears
  5. Shows current status and new status
  6. User clicks "Toggle Status"
  7. patientList updates status value
  8. StatusBadge changes (active → inactive or vice versa)
  9. Confirmation modal closes
  10. Action menu closes

ARCHIVING PATIENT:
  1. User clicks three-dot menu (⋮)
  2. Action menu opens
  3. User selects "Archive" (orange text)
  4. Orange confirmation modal appears
  5. Message: "Patient will be archived and hidden..."
  6. User clicks "Archive"
  7. Patient's archived flag set to true
  8. Filter logic excludes patient from list
  9. Patient disappears from view
  10. Data preserved for future recovery

DELETING PATIENT:
  1. User clicks three-dot menu (⋮)
  2. Action menu opens
  3. User selects "Delete" (red text)
  4. Red confirmation modal appears
  5. Strong warning: "Cannot be undone..."
  6. User clicks "Delete"
  7. Patient removed from patientList
  8. Patient permanently deleted
  9. Action menu closes
  10. List refreshes without patient
